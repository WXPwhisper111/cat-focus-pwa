# V0.2 M2：每日欢迎与自动签到

完成日期：2026-10-21。完成后停止，没有商城、连续签到展示/额外奖励、累计奖励、成就或补签。

## 已实现

- 每个设备本地自然日首次启动自动签到，固定获得5猫爪币；关闭、刷新、同日重新打开和多个标签并发不会重复发币。没有手动领取操作。
- 签到事务提交成功后才展示“今日签到成功！”、“+5 猫爪币”和欢迎文案。主按钮只关闭并切换专注页；关闭按钮和Esc只关闭欢迎界面，不操作计时。
- 运行/暂停中的会话不弹模态框，改用非阻断提示；不暂停、不结束、不重置会话。已有其他弹窗时，成功欢迎延后到它关闭；避免堆叠弹窗。
- 已领养时复用主陪伴猫的idle播放器，关闭/销毁时清理动画，隐藏/后台行为沿用播放器。未领养时使用暖色猫爪SVG装饰，没有默认猫咪。
- 前台跨日、visibilitychange、focus、pageshow时检查；后台不反复检查。成功日期在内存缓存，日内计时刷新不会重复访问数据库。失败后不缓存成功日期，前台返回可重试，常规检查失败最多每分钟重试一次。

## 数据与原子性

数据库仍为5，备份仍为5。签到历史保存在settings/dailyCheckins，使用完整数组记录每个日期，而非仅最后一次日期。每条包含：

```json
{
  "date": "2026-10-21",
  "claimedAt": 1792542600000,
  "reward": 5,
  "transactionId": "daily_checkin:2026-10-21"
}
```

示例仅解释结构，不写入应用。claimedAt为实际领取的毫秒时间戳；日期通过设备本地年/月/日获取，不截取UTC日期。历史日期保存后不随时区变化重新解释。

checkinToday在同一readwrite事务中检查钱包和完整历史，写wallet余额/收入、walletTransactions的daily_checkin:日期流水，以及settings签到记录。固定流水ID和跨标签共享的事务锁共同去重。任何一步失败均回滚，不返回created:true，因此不会显示成功。

签到不增加XP，不修改专注记录、有效时长、5分钟币进度、等级或领养。首次M1旧币迁移后，可以正常签到获得5币。系统日期回拨到历史日期不会重复领奖；没有联网时间源和复杂反作弊，手动改到新的日期仍会被当成本地新日。

## 备份兼容

v5钱包流水已具备签到的日期键、奖励和领取时间，因此无需新增备份字段或版本。导出完整保留签到流水，恢复时同步重建settings历史，避免恢复后同日再次领币。已有不含签到数据的M1备份仍可导入。

首次启动会先领5币，所以允许“只有未消费签到奖励、没有专注凭据/余量或其他收支”的钱包恢复备份，并按日期保留本地签到奖励。备份已包含相同日期则只保留一笔；不同日期合并一次。重复导入同一备份不增加奖励。已有额外专注收入或消费的钱包仍执行M1冲突保护；活动会话仍阻止覆盖不同的钱包。钱包、签到历史、类别、记录和领养恢复处于同一导入事务中。

## 验证结果

### 自动化与构建

124项测试、22个文件通过；生产构建通过。原有M1和计时/统计/类别/领养/动画测试全部运行。新增13项测试覆盖：

- 首次5币、同日去重、数据库重开、跨日和回拨日期，完整历史记录。
- 上海本地凌晨与UTC不同日期，以及本地午夜边界。
- 多连接并发领取一次。
- settings、wallet、walletTransactions分别写入失败时全部回滚，失败重试不误显示成功。
- 不调用网络的离线签到，签到不改变活动会话/历史/XP或专注余量。
- v4旧币升级为0后，首次签到正常获得5币。
- 签到备份恢复、日期去重、恢复M1备份时保留首启奖励、重复导入及消费后冲突保护。
- 事务完成前不触发成功回调；失败退避和前台重试。
- 欢迎主按钮不启动计时，同日不重复欢迎；跨日专注不中断；其他弹窗打开时延后欢迎。
- 主陪伴猫idle正确，关闭/Esc/销毁取消播放器。
