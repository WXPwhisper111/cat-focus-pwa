# 猫咪小屋 V0.1 房间基准场景

后续状态：已于 2026-10-20 接入 PWA 的独立房间组件，详见 [接入与验收说明](integration.md)。以下内容保留首次静态校准时的设计依据与结果。

完成白天纯场景版 `room_scene_v01_clean.png` 与开发标注版 `room_scene_v01_annotated.png`，均为 1024 × 768 不透明 PNG。二者由相同的 A 版画布生成，B 版仅叠加开发辅助标记。

本次是开发场景拼装：独立 HTML Canvas 按固定坐标直接使用已有 PNG，最近邻等比缩放，未用生成模型重绘猫咪、家具或背景。仅在猫咪脚下添加一层简短像素接触阴影。未加入应用 UI、夜景或交互逻辑，未修改 PWA 的任何现有业务源码。

## 比例核对和限制

- 猫窝可见尺寸约 247 × 110，宽度约为当前猫咪可见宽度的 1.94 倍，适合表现小型软窝。两只碗各约 81 × 34，猫抓板约 110 × 99，未发现必须重画才能使用的素材比例问题。
- 墙上置物架与摆件组相对首次拼装缩小到 75%，避免书本接近猫咪体高；二者维持相同比例与原叠放偏移。每张图层的实际坐标均在 `layout.json`。
- 地毯浅而宽，适合横排错位停留；三猫站位验证通过，不代表已验证三只猫同时自由穿行、转身或互动。当前房间地板纵深有限，未来运动需要避让/等待；不能把这张静态图当作导航验证结果。
- 通行带只有 28 像素深，当前 18 像素脚底投影可通过；建议仅通行、不停留，并在后续导航中限制对向会车。若实际碰撞体更深，应先加宽通行带或调整底图地板占比，再接入运动。
- 三猫完整画布按 144 × 144 校准，横向余量较紧。未来较大猫种应限制显示尺寸，或重新校准三猫站位，不要直接放大现有猫咪。
- 原房间底图踢脚线约在 y485–511，木地板从约 y512 开始，略高于最初 68%（约 y522）的设想；本版沿用已有底图，功能区从 y520 起，不改背景。若以后调整墙地比例，须同步更新所有地面坐标。

## 检查与复现

`validation.json` 记录了四区互不重叠、中央最大、三猫框互不重叠且均在活动区内、餐具前方站位可用、WC 接通行带、猫爬架不碰墙饰，以及输出尺寸和不透明性检查；全部通过。可见包围盒按原素材 Alpha >= 16 计算。最终还目视检查了两个版本。

`layout.json` 为布局基准；`scene.html` 为独立场景渲染源；`render.cjs` 通过本地 HTTP 与无头 Chrome 导出两个 Canvas。复现时须有 Node.js、Playwright 和本机 Chrome，`CAT_SCENE_PLAYWRIGHT` 可指定 Playwright 模块路径，`CAT_SCENE_BROWSER` 可指定浏览器可执行文件。本地服务仅监听 127.0.0.1，并在导出后退出。
