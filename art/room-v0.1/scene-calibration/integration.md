# 房间组件接入与验收

此文记录首次将房间接入专注页时的结果。当前阶段 A 已将房间移至独立“猫咪小屋”，专注页恢复单猫卡片；最新实现与验证见 [阶段 A 说明](../stage-a/README.md)。

日期：2026-10-20。布局唯一依据为本目录 `layout.json`，原有两张场景合成 PNG 保持为视觉对照。

## 运行方式与边界

按项目 README 安装依赖，运行 `npm run dev`；生产离线检查使用 `npm run build` 后的 `npm run preview`。打开专注页即可看到分层白天房间。暂停后猫咪在地毯原地睡觉，恢复后原地待机；未开始专注时也播放 idle。

运行时按配置顺序使用独立图层，1024×768 逻辑坐标统一转换为百分比，场景固定 4:3。陪伴文案在场景外，画布边界以外的地毯等内容统一裁切。仅一只猫，没有喂食、切窗帘、夜景、移动、家具替换、商城或 WC 行为。

`src/room-scene.ts` 的 `createRoomScene(initialState, options?)` 返回 `element`、`updateState(state)`、`destroy()`。组件只接收 `idle | sleep_loop`，不访问 IndexedDB 或修改奖励。专注页重渲染时复用播放器和 DOM，离开页面时销毁；后台停止绘帧，前台从当前姿态继续，计时继续由已有时间戳逻辑计算。

每个图层有稳定的 `data-room-object` ID。`roomHotspots` 预留物品可见区域和屏幕最小 44px 目标，食盆和水盆独立定义；只有显式传入热点及操作回调时才创建按钮，应用首轮没有传入，因此没有假交互。后续启用相邻热点时还需处理扩大的点击区域互相重叠。

## 手机动画与校准

- 原始素材保留在 `public/cat/`；手机派生资源在 `public/cat-mobile/`。10 张均为 288×288 RGBA 无损 WebP，最近邻缩放，不裁切、不拉伸原画布。
- `cat-frames.json` 保存每帧原始 Alpha 边界、前爪接触位置、源图锚点和场景偏移。idle 6 帧、4 FPS；sleep_loop 4 帧、2 FPS。
- 以原布局 idle 首帧 `[440,572,144,144]` 为基准，逻辑脚底 `(512,716)`。原图前爪下边界为 1242，画布底部余量为 12；各帧源锚点取 `[627, pawBottom + 12]`，场景 y 偏移为 `(1242 - pawBottom) × 144 / 1254`。保持水平画布中心，不按变化的尾巴轮廓重新居中。
- 前爪区域检查使用原图 x=700–1199 的 Alpha≥16 可见像素；睡眠帧尾巴低于前爪，不能直接以整图 Alpha 最低边界代替前爪接地点。`cat-calibrated-contact-sheet.png` 展示全部帧及统一前爪接触线，原有呼吸和尾巴形变保留。
- 原 10 帧共 **10,510,629 字节**；派生资源共 **627,284 字节**，减少约 **94.0%**。统计页两处头像也使用派生首帧。

重新生成需 Python 与 Pillow：

```powershell
python scripts/prepare-room-cat.py
npm test
npm run build
```

脚本会验证记录的接地点，并生成派生 WebP、校准 JSON 和接触线预览。更新原始姿态后应先目视检查前爪位置，再调整脚本中的接地点，不能直接用整图底边自动替代。普通运行和构建不需要 Python。

## 缓存与离线修复

生产预缓存包含全部 13 张实际房间图层和 10 帧派生动画；原始猫咪 PNG 仍保留在发布目录，但不会预缓存，应用也不再请求它们。此次完整预缓存共 32 项，约 4.21 MB（包含图标及保留的夜景素材）。

首次停服重开曾出现白屏。检查确认资源已缓存，但 Vite 返回 `Vary: Origin`，预缓存与模块脚本请求的 Origin 差异导致缓存漏匹配。现已限定为当前版本明确列出的公开静态 URL，在当前版本缓存内以 `ignoreVary` 匹配；未列出的 URL 不走该规则。缓存内容仍按资源内容生成版本，不涉及用户数据库迁移。

修复后重新验证：Service Worker 已激活；原始大帧未缓存；停服后页面、脚本、底图、派生帧仍返回成功；刷新及关闭标签页后重新打开都能恢复暂停会话和睡眠动画，恢复运行后 idle 正常。
