# V0.3 阶段 3：自主行为调度器

## 实现与边界

- `src/room-autonomy.ts`：每个小屋实例一个可取消的调度计时器。首次 8–10 秒、完成后 10–20 秒、启动间隔 5–8 秒；最多两只猫同时活动。排除选中的互动猫；家具点击延后启动 8 秒。不自动抚摸。
- `src/room-behavior-config.ts`：集中维护并发上限与既有动作配置。
- `src/room-behavior.ts`：全部自主请求复用原有执行器、真实素材和传送控制器。手动请求可安全接管自主动作，遇到传送先等待淡入完成；占满两席时可安全结束一个自主动作让出执行名额。
- `src/room-anchors.ts`：同时管理临时预留与已到达的稳定占用；同猫重新播放失败时恢复原占用，不允许其他猫抢占同一餐具区域。
- `src/room-locations.ts`、`src/storage.ts`：在现有设置存储保存猫 ID → 稳定家具锚点 ID，校验居民身份、真实锚点和共享区域容量。不保存透明度、帧序号、行为任务或冷却倒计时。
- `src/main.ts`：装配家具装备检查、调度器、生命周期和串行位置保存；切页销毁，后台取消当前任务并归一到最近已完整淡入的位置；前台重新等待首次延迟，不补演后台动作。
- `src/room-scene.ts`：图片解码前按已知坐标定位，避免恢复时短暂闪回原站位；原站位顺序与主陪伴猫排序分离。
- `src/room-interaction.ts`、`src/room-interaction-panel.ts`：面板同步显示自主活动状态，取消和手动行为仍走同一执行入口；选中不改变主陪伴猫。

行为结束后保留目标位置并播放 idle。若只有上一次动作可执行，且仍占用家具，执行器会把该猫传回自己的原站位腾位，然后正常冷却。这样三个区域都被稳定占用时不会永远僵住。

真实 V2 素材只有吃饭、喝水、抓挠 loop 和抚摸 once，没有 enter/exit。已有可选阶段组合能力保留，运行时不虚构片段。三只猫均有自己的睡眠动画。

数据库仍 v5、备份仍 v6。稳定位置按现有“其他本机设置不导出”的语义处理，JSON 备份不含这些纯展示位置；跨设备恢复后从默认站位开始，所有权、入住、钱包等保持原备份规则。本阶段没有修改奖励、计时或购买算法。
