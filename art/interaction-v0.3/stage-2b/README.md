# V0.3 阶段2B：传送与手动行为闭环

日期：2026-10-21。完成后停止，未开始阶段3。

## 已实现

- 手动吃饭、喝水、抓挠、睡觉及一次抚摸。互动猫独立于主陪伴猫，不改变所有权、入住、钱包或奖励。
- 统一执行器接收猫ID、行为、manual/autonomous来源、家具和可选锚点ID。生产界面仅发送manual，没有随机选择或自主调度器。
- 标准流程为校验→预留锚点→预加载→淡出→完全透明后换位→淡入→可选enter→有限循环/单次→可选exit→回原站位idle→释放锚点。
- **最新V2实际没有enter/exit**。生产配置明确缺省，运行时跳过，未伪造资源。测试以已有同猫单次Clip作为测试执行器样本，验证未来可选阶段的组合顺序；不向正式素材目录新增任何映射。
- 猫窝使用每只猫自己的真实sleep_loop，三只均有资源。地毯没有新增动作；抓挠UI映射到正式素材scratch。

## 配置与坐标

| 行为 | 当前时长 | 放置依据 |
| --- | --- | --- |
| 吃饭 | 4.8秒／2个2.4秒循环 | 食盆布局锚点与本猫嘴部参考 |
| 喝水 | 6秒／2个3秒循环 | 水盆布局锚点与本猫嘴部参考 |
| 抓挠 | 3.84秒／2个1.92秒循环 | 猫抓板布局锚点与本猫前爪参考 |
| 睡觉 | 9.6秒／2个4.8秒循环 | 猫窝局部脚底锚点 |
| 抚摸 | 单次2.4秒 | 当前所在位置，无传送 |

时长集中在`room-behavior-config.ts`；传送淡出150ms、淡入180ms也集中配置。循环按素材时长向上取整至完整周期，不用固定延时决定动作结束。通用播放器新增`iterations`，仍共用原RAF和前后台暂停机制。

锚点保存为家具图层的局部比例，读取实际1024×768布局计算房间坐标。吃饭/喝水/抓挠使用动作接触点解算精灵矩形和脚底；脚底基准与嘴/爪接触参考分开，不锁死逐帧动作。睡觉使用猫窝脚底校准点。没有新增图片。

每个家具支持锚点数组；目前每件物品配置一个锚点。食盆、水盆共享food互斥组，防止两只猫挤在相邻碗旁；其他配置和扩展锚点可使用各自占用组。足迹检查同时保护当前猫位置、已预留目标和各猫返回站位。不是完整身体碰撞或寻路系统。

## 取消、异常与生命周期

- 位置切换由Web Animations API的`finished`事件推进；4秒前台看门狗只用于异常恢复，不是正常流程时钟。
- 传送中不接受同猫新行为。取消会终止过渡并恢复可见姿态，执行器继续完成回位/资源清理；控制器保持恢复中直到清理完成，再允许新动作。
- 隐藏页面或pagehide时暂停过渡和看门狗；恢复前台/pageshow继续。播放器本身仍暂停后台动作时间。
- 不支持WAAPI、过渡异常、加载失败或完成事件缺失时恢复可见原站位；销毁中止动画、移除监听和定时器、释放锚点。等待加载或透明阶段的异步工作可以取消，旧结果不能重新启动动作。
- 切页或主陪伴排序导致房间重建时，先销毁旧执行器，恢复可见位置并释放临时资源，再销毁场景。临时行为不写存档，刷新后从idle开始。
- 明确通过统一接口传入的autonomous循环可被manual请求安全取消、回位后替代；传送和manual行为不会被新manual直接覆盖。此分支只为未来接口与测试预留，生产没有自主请求来源。
