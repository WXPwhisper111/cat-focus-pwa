# 启动页 V0.1 验收记录

日期：2026-10-22。

## 检查与实现

沿用 Vite、TypeScript、原生 DOM/CSS。入口 src/main.ts 原先顺序为打开 IndexedDB、创建现有控制器、恢复/结算会话和读取数据、自动签到、安装前台监听和计时更新。没有独立启动页。

正式图标使用 manifest.webmanifest 已引用的 public/icon-512.png。未新增图片、依赖或改变 manifest、数据库 v6、备份 v8、缓存策略。

### 修改文件

- src/startup.ts：独立启动展示控制器，120ms显示阈值、串行重试、定时任务清理。
- src/startup.css：浅暖背景、正式图标、固定HTML文案、手机安全区域、短屏和横屏布局。没有入场动画，因此不存在额外运动，也不需要强制等待。
- index.html：主挂载点初始 hidden/inert，避免尚未准备好的交互出现。
- src/main.ts：将原初始化代码包装为可重试函数，初始化期间暂停页面渲染和欢迎/结算弹窗展示；完成后渲染现有页面并恢复原有监听。失败销毁本次创建的控制器并关闭数据库连接，重试仍调用同一初始化流程。
- tests/startup.test.ts：快/慢初始化、固定文案与图标、失败重试防重、后台事件不重播、销毁清理。
- tests/startup-integration.test.ts：真实入口部分初始化失败后的清理、重试与暂停会话保持；全局计时任务只创建一次。
- art/startup-v0.1/preview.html：隔离视觉验收页面，复用正式组件，不连接数据库、不进入生产构建。Enter模拟初始化完成，Escape模拟失败，失败后可点重试。
- README.md、本文及截图：维护与验收说明。

## 展示和恢复规则

每次完整加载页面需要实际初始化时运行一次。120ms内完成则不显示启动页；超过后显示，完成即移除，无最短展示时间。失败立即显示友好提示与重试入口。

后台恢复不重新执行启动入口，不创建启动页；仍由原有前台处理恢复会话、检查签到。页面被系统销毁后的重新加载属于真实冷启动。

初始化就绪之前不显示主导航、计时控件、签到欢迎或结算弹窗。成功之后沿用原有页面流程，不启动计时器、不重置任何业务数据。

- npm test：47个测试文件、232项通过；包含原有计时、统计、任务、钱包、签到、商城、猫咪行为与备份测试，以及新增5项启动测试。
- npm run build：通过，包含 tsc --noEmit、Vite生产构建和SW生成。项目没有独立lint命令。
- 最终产物：index-Cp5Ij9QL.css / index-Dq5NkZy4.js。
- 已检查正式图标及本次CSS/JS均存在于自动生成的SW预缓存清单，不需要修改缓存策略；视觉预览HTML未进入dist。
- 浏览器实际应用在隔离4213端口打开，初始化后显示既有签到欢迎并进入主界面；正计时开始→暂停→刷新仍保持暂停，切到统计再回专注能够继续，启动页已移除。未操作用户4195端口。
- 浏览器视觉验收使用独立预览来稳定观察“初始化尚未完成”的状态：390×844、320×568、844×390、1280×800。图标解码为512×512；短屏/横屏/桌面内容尺寸与视口一致，无横向或纵向溢出。固定文案全部为HTML文本。
- 预览中模拟失败显示明确错误与重试；点击重试后模拟完成正常进入测试主界面。
- 真正的慢DB和失败重试由自动集成测试验证；浏览器视觉预览的模拟等待不是正式应用的固定延时。
